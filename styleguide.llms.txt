# Runbooks — design system reference

Source of truth for building conformant UI. Interactive version: /styleguide
(dev-gated, off in the default container), organised by atomicity —
Foundations → Layout primitives → Atoms → Molecules → Patterns.
Spec: specs/runbooks-design-system.md.

## Stack

Go + templ + plain CSS. No framework, no Tailwind, no utility classes.
CSS source: public/css/src/ → bundle: public/css/bundle.css (committed).
Build: `mise run css` / `mise run js` / `mise run build`.

## Palette — seeded from the mallard, dark-first

Roles, never raw colour. `:root` is the DARK theme; `html[data-theme="light"]`
overrides it.

  --accent         brand fill (primary buttons, active nav)
  --accent-strong  brand used as text, icon or border (readable on the bg)
  --accent-lt      translucent brand tint (active/selected backgrounds)
  --on-accent      text on an --accent fill
  --link           links and info
  --success        ok status        --warn   warn status
  --danger         danger status
  --bg / --surface / --surface-2 / --nav-bg   page, raised, chrome
  --text / --muted / --nav-text / --nav-muted
  --border / --border-strong

Rules:
- Status is NEVER the brand accent.
- Code surfaces stay dark in BOTH themes: use the constant --code-* tokens
  (--code-bg, --code-border, --code-text, --code-var-filled, --code-var-secret).
  Never put a theme role inside a code block — it renders dark-on-dark in light.
- Body text and chrome meet WCAG AA on their themed background.

## Typography

  --font-sans  "Atkinson Hyperlegible Next" (UI, prose)
  --font-mono  "Atkinson Hyperlegible Mono" (commands, tokens, identifiers)
  --mono-weight  450 default; 600 when data-code-weight="bold"

Self-hosted variable woff2, latin subset. Compact scale --text-2xs..--text-2xl.

## Tone and language

British English throughout — prose, identifiers and user-facing copy: colour,
behaviour, licence, enrol/enrolment, labelled. American spelling only where the
language itself demands it (CSS `color`, `center`).

Copy is read under duress: titles lead with the symptom, not the mechanism, and
instructions are short and imperative. Keep real code and identifier names.

## Spacing, size, radius, shadow, motion

  --space-0..7 (0,4,8,12,16,24,32,48)   never raw px for gap/padding
  --size-app-sidebar / --size-app-header / --size-detail-min|max
  --ctrl-pad-y   the vertical padding that sets control height (btn, input, select)
  --radius-sm|md|lg|pill   --shadow-sm|md|lg   --duration-fast|base   --ease

## App shell & layout contract

Pages render inside the shell: `<aside class="sidebar">` + `<div class="main">`,
with a `.main-header` and a scrolling `.content` (which sets scroll-padding-top so
anchored section links don't land flush against the header). A page with no notes
column marks its main `.main--full`, collapsing the body grid to `sidebar | main`.

Layout uses the primitives in layouts.css only — never bespoke flex/grid in a
component: .stack, .cluster, .row, .inline-icon, .grid[data-cols], .grow,
.truncate, .list-row, .detail-shell.

Contextual chrome belongs to the context, not the component — e.g. the sidebar
footer divider is `.sidebar .appearance`, so the atom can be shown elsewhere (the
styleguide) without carrying a border that only makes sense in one host.

## Components

  buttons   .btn (+ .btn-primary | .btn-ghost | .btn-danger, [disabled])   button.css
  badge     .badge-ok | .badge-warn | .badge-danger | .badge-info           badge.css
  alert     Alert(weight, intent, title, msg). Intent (danger | warn | info |
            success) is independent of weight (inline | panel | banner); panel is
            the default and carries no modifier. The intent sets --alert-color,
            the weight sets the frame: inline = field/form validation, panel =
            the operation failed but the page works, banner = a blocking
            condition. The banner's bleed into a card belongs to the host
            (.auth-card > .alert-banner), not the component. A notice is a prose
            callout; an alert is state.                                  alert.css
            JS: showLiveAlert(title, err) fills the page's [data-live-alert]
            panel; progress text stays .auth-status, not an alert.
  fields    .form-field + .form-label + .text-input | .select-input, plus
            .form-hint / .form-error                                      forms.css
            .form-row grows the fields to fill the row; an inline action aligns
            to the control baseline (align-self) and controls take height from
            --ctrl-pad-y, so a button lines up with a field. Fields align by
            their tops, so labels and controls match even when one field has a
            hint (the hint is absolute, out of flow; the row reserves space).
            The select uses our own inset chevron (appearance: none).
  dialog    <dialog class="dialog"> with .dialog-header/-body/-footer         dialog.css
            Server-rendered: data-dialog-open="id", data-dialog-close.
            JS confirmations/prompts: showDialog({ title, message, danger, input }).
  notice    Notice(variant, msg) → .notice-info | .notice-warn | .notice-danger
  code      CodeBlock(label, template, lang) → per-block done checkbox
  step      Step(n, title) numbered card; RollbackStep(title) danger card
  toc       Contents — the step list at the top of a runbook (three or more steps)
  table     TableBlock(headers, rows)        list   ListBlock(items)

## Appearance preferences

Applied as data attributes on <html> before first paint; localStorage keys are
`runbooks-theme` (light|dark|system, default dark), `runbooks-code-weight`
(regular|bold, default regular) and `runbooks-text-size` (small|medium|large,
default medium). Text size sets `--text-scale`, which moves the type scale and
nothing else.
